# 理由图提议器盲区调研：根因分解与改进方向（Mak L8）

> 触发问题：v3/v4 探测器的流派覆盖大量依赖脆弱的 GDF topk 提议器兜底——理由图挖掘引擎
> 对 天平/图书馆/减速重炮 等主流派完全不提议。本文定位根因并回答：
> 应改进理由图（边类型/权重等机制性提升），还是换策略。
> 证据来自对 `reason_graph.py` / `ReasonMine.cpp` / `proposer.py` 的源码分析与挖掘消融实验
> （`out/exp/engines_pairs.json`、`engines_noquota.json`），强度结论均以 `bazaararena_meta` 真值复测。

## 0. TL;DR（判断）

1. 盲区**不是"缺边"**。除 恶臭蘑菇（真孤立节点）外，天平/图书馆/股骨/时间之砂/魂戒 在图中都有边，
   挖掘器也能生成含它们的闭包——它们在**评分与截断**阶段被系统性埋掉。只加边类型不修评分/截断，没用。
2. 根因是三层结构性问题：**数值核心只认字面量**（使能件/公式件 core_score=0）、
   **供能边语义被压扁**（一律 0.5，不含量级与目标信息）、**挖掘目标 = 大闭包 × 强核心 + 头部配额**
   （使能组合永远排在尾部，被配额批量裁掉）。
3. 但即使把这三层都修好，也不应把理由图当作主提议器继续加码：本轮 12 个"文本上成立"的机制协同
   手工假设在真值下 **0-280 全败**——静态机制先验对 L8 强度的预测力极弱，而真值评估
   （`bazaararena_meta`）约 3.4 万局/秒。**搜索驱动的发现比先验驱动的发现便宜且可靠。**
4. 建议：**主路线改为真值驱动的 BR 搜索提议器**（PSRO 外环已验证，提议器是唯一瓶颈）；
   理由图只做两项机制性修复（静态估值器、格子化覆盖）后降级为变异先验/解释/装配约束层。
   详见 §3。

## 1. 盲区根因分解（证据链）

### D1. 数值核心只认字面量 → 使能件/公式件 core_score=0

`reason_graph.core_roles` 的强度分来自 `tier_value` 对 `Damage/Poison/Burn/Regen` 等字段的**字面量**读取。
强度藏在公式或光环里的物品全部得 0：

| 物品 | 强度来源 | core_score |
|---|---|---|
| 魂戒 | aura 公式：毒 = Side Regen（`Auras[].value` 是公式，无字面量 Poison） | 0 |
| 智者之杖 | 伤 = Custom_0 × Custom_1（乘积公式） | 0 |
| 时间之砂 | 纯减速控制，无伤害/资源数值 | 0 |
| 天平 | 全体充能（供能，非"产出"） | 0 |
| 图书馆 | 纯光环（CD 操纵） | 0 |
| 采掘工具 | 纯充能供能 | 0 |

而挖掘播种要求 `core_score > 0`（`ReasonMine.cpp` 种子循环）——**这些物品永远不能成为种子**，
只能作为邻居被捎带，且只带 0.5 弱边（见 D2）。

### D2. 供能边一律 0.5，量级/目标信息全被压扁

`feed` 边不区分：天平（全体充能 2s，条件居中）、实验室（全体充能 2s）、采掘工具（相邻遗物 3s）、
沙漏（相邻 -12% CD）、图书馆（非武器 -1.5s CD）——**通通 0.5**。实测边表：
天平 的 38 个邻居全是 0.5；{天平,永恒火炬} 闭包分 = 1.0（min_pair 下限）。
天平/图书馆在图中实际上"连接良好但毫无权重"。

### D3. 挖掘目标 = 大闭包 × 强核心，配额从头部截断 → 使能组合必然被埋

评分 `score = 闭包边权和 + 8 × max(core_score)`：闭包分随成员数增长，core 奖励被 8 倍放大，
于是 4 件强核心闭包（20–30 分）永远压过 2 件使能对（1–4 分）；排序后配额从头部截断。

消融证据（`--family-quota 99 --channel-quota 99 --core-bonus-weight 0`）：

- 2 件播种阶段实际生成 **2119 个对**（Python 逐行复刻验证），含 {天平,永恒火炬}（1.0）、
  {股骨,时间之砂}（2.0）、{魂戒,…}（9 个）等——**挖掘器本来"看得见"这些组合**；
- 但 C++ 输出恰好 **396 = 4 通道 × 99**（Damage/Burn/Poison/Regen 各 99）：配额被各通道高分对占满，
  低分对整批裁掉——输出里 1.0 分对 0 个、1.5 分对仅 4 个，≥2.5 分对与原集合完全一致（142/46/10/7）。
- 生产参数（quota 3/8 + core bonus 8.0）下复刻结果 = **32 个引擎、全是 4 件高核心闭包**，与现状一致。

### D4. 真正的边缺失只有两类

- **孤立节点**：恶臭蘑菇（双方 +CD 光环）0 条边——"meta 相对"机制无任何通道。
- **负向/纯度机制**：图书馆对武器 +CD、魂石家族互斥——无负边，靠 `templates.py` 人工注释承接
  （reason-graph-review.md §5/§7 已自承"不表现为协同边"）。

### 关键反证：pair_probe 的 92% 覆盖率为什么没暴露这些

pair_probe 测的是**两两对照替换的边际胜率**（阈值 ±0.2）。使能件的价值在闭包层而非两两层
（采掘工具单换的边际 ≈ 0，但它是遗物引擎的充能枢纽）——该方法**原理上测不到 D1–D3**，
92% 不能用来论证"边够了"。

## 2. 为什么不应继续加码"静态理由图"作为主提议器

1. **静态先验 → 强度的转化率实测极低**：本轮从 mak.yaml 机制阅读构造的 12 个协同假设
   （魂戒再生、火爪灼烧、日光矛、坩埚杂烩、镜子复制、冰霜毒爆、彩虹棱镜、先祖遗物、驼鹿再生、
   恶臭重炮×3），对 7 个真值精英 **0-280 全败**（`out/exp/meta_probe_out.jsonl`）。
   更精细的静态建模只会让提议器更自信地产出同样要被真值过滤掉的候选。
2. **真值评估太便宜**：3.4 万局/秒，一个卡组对 σ 池（≤12 个对手 × 40 局）的加权评估 < 0.1s；
   v3 DO 外环 6 轮收敛 ~4 分钟。瓶颈从来不在评估（bazaar-meta-evidence.md §0/§3.1 已定论）。
3. **有些盲区是静态方法的原理性边界**：恶臭蘑菇这类"强度取决于对手频率分布"的机制，
   任何静态图都无法估值——它只能在对 meta 的实测中被发现（本轮实测：该方向 L8 无强度，0-280）。

## 3. 建议（按优先级）

### R1（主路线）真值驱动的 BR 搜索提议器

把 best response 从"提议器采样"升级为**以当前 σ 加权胜率为目标的局部/束搜索**：

- 起点：当前精英池 + 挖掘引擎 + GDF topk（多起点覆盖不同 basin）；
- 变异：换 1 件 / 换填充 / 换位（排列走 perm_constraints 等价类代表）；
  **理由图在此提供软先验**（优先变异出理由边连通的替换），不再负责"发现流派"；
- 评估：`bazaararena_meta --serve` 自适应波次，目标 = 对 σ 的加权胜率 + exploitability 增量；
- 预算量级：单候选 ~0.1s，一轮 BR（百级候选 × 数次迭代）分钟级——完全在现有算力内。

这把"覆盖流派"的责任从静态先验转给实测目标：GDF topk 提议器可以退役为普通起点之一，
其路径脆弱性（bazaar-meta-evidence.md §2.4）不再是要害。

### R2（机制性修复）数值核心 → 静态估值器

把 `core_roles`/`tier_value` 的字面量读取升级为**公式 AST 在 L8 规则下的静态期望估值**：

- 公式求值复用 C++ `engine/formula/` 的 AST（Custom 乘积、任务门控、光环 value 公式走同一路径）；
- 资源引用（Side/Opp Regen、Poison 等）取**经验分位数**——从真值对局统计精英对局的典型资源量
  （比 `TRIGGER_FREQ` 拍脑袋权重有据得多）；
- 收益：魂戒/智者之杖/时间之砂类物品 core_score 不再恒 0，D1 假阴性消除。
  这是统一求值器，不是为单个物品打补丁。

### R3（机制性修复）配额截断 → 格子化覆盖（MAP-Elites 化）

把"全局按分排序 + family/channel 配额"改为**（核心通道 × 引擎角色）格子各留 top-K**：

- 引擎角色轴：数值核心 / 纯供能（feed-only）/ 转换（resource 缩放）/ 控制（Slow/Freeze 产出）——
  角色从画像字段机械判定；
- 使能组合不再与强核心闭包在同一根排行榜上竞争，D3 的结构性埋没消除；
- 天平对（1.0 分）在"供能角色"格子里是头部而非全局尾部。

### R4（正确性收益，非覆盖收益）负向边

为"抑制/纯度"机制建负边（图书馆→武器、恶臭蘑菇→高频件、魂石家族互斥），
用途是**自动推导装配约束**（替代 reason-graph-review.md §5 的人工注释），
并让挖掘器能产出"图书馆 + 全非武器"这类合法性内建的引擎。不指望它提升覆盖。

### 明确不做

- 不为 恶臭蘑菇类 meta 相对机制建静态通道（原理上无法估值 + 实测无强度）；
- 不再为单个流派手工补模板（v1 模板库退役的教训）；
- GDF 加深枚举（pair-seed 等）可作即期止血，但不解决提议器结构问题，优先级最低。

## 4. 验证计划

1. **R2+R3 消融**：重跑 `--mine-engines`，检查当前真值流派（冻结控制/减速重炮/自毒注射/自毒武器/毒/
   药水装填/图书馆壳/天平充能）的代表引擎是否出现在输出中（当前缺席：天平/图书馆/股骨/时间之砂系）。
2. **R1 端到端**：BR 搜索提议器接入 `open_do.py` 跑一轮，**去掉 GDF topk 提议器**，
   对比引擎覆盖率与 σ 质量（v4 口径：validator 引擎覆盖 7/9，真值支撑股骨被精确命中，
   但减速重炮/图书馆壳/天平充能靠 GDF topk 兜底）；
   成功判据 = 无 GDF 提议器时覆盖不降、σ 支撑不含非法卡组。
3. **回归**：`mine_engines_test.py` 的 10 已知流派覆盖断言更新为新的格子化口径；
   `reason_token_census.py` 对新增边类型/估值词元保持三分类封闭。
