## 0. TL;DR

1. 「优质」必须是 **meta 相对**的：实测上半区 79 个精英卡组间存在 **1250 个非传递 3 循环**（阈值 0.6）；
   近似混合 Nash 的支撑仅 3 个卡组（炼金炉 0.51 / 先祖墓 0.43 / 腐朽圣像 0.07，exploitability≈0.0004），
   且支撑成员 ≠ 平均胜率头部——单一标量排名在此环境无意义，PSRO/元博弈方向**被实证确认**。
2. GDF 的**排序信号失真**：锚点内部循环赛得分（RR）与真实 meta 胜率的 Pearson 相关仅 **0.30**（解释方差 <10%）。
   「同 beam 内卷排序」基本不能预测外部强度，贪心每档的截断决策大部分是在噪声中进行的。
3. **Bo5 一次性淘汰 ≈ 抛硬币**：21 局系列赛对均势对局的标准差达 0.09–0.13，Bo5 更差（≈0.2）。
   但成对胜率呈 U 型分布（约 43% 对局一面倒），**评估预算应按对局自适应分配**而非均匀 BoN。
4. **位置价值是离散双峰**：天平居中与否 = 61-0 的碾压差；而同属居中类的排列互换在多 seed 下统计不可区分。
   排列层应从「逐个比较排列」改为「从机制 AST 提取位置约束类，每类只评代表」。
5. **流派纯度**：跨流派朴素融合（自毒注射×药水引擎、注射×减速控制）对 5 个顶级卡组全部 0-31。
   卡组 = 「流派引擎核心（4–7 格，需临界质量）+ 流派无关填充」，搜索应以**引擎模板**为单位而非裸物品。
6. 算力不是瓶颈：CLI 单局约 40ms，进程级并行（GDF 的 `--workers` 实为死代码）后 136 锚点枚举从约 2.6 小时降到 **13 分钟**。
   瓶颈在搜索与评估设计。

## 0.1 勘误与复测（2026-08，阶段 1 管线）

**首版实验矩阵的对战条件有误**：实验 harness 的转换函数只识别扁平 `quest` 键，而矩阵卡组使用的是
嵌套 `attrsOverride` 结构——**全部任务进度与 overridable 覆写在首版 10296 场对战中被静默丢弃**
（任务物品以 quest=0 上场、overridable 未按等级缩放）。该问题在阶段 1「测量底座」管线的
新旧矩阵对照中暴露（先祖墓卡组平均胜率 0.014 → 复测 0.950，完全反转）。
本文数据已按修正管线（`scripts/meta_search/`，8911 对、自适应预算、Wilson CI 控制）复测更新。
此事本身是「先修测量、再改搜索」路线最直接的证据。

复测后**仍然成立**的结论：非传递性（循环数 1250，密度同量级）；U 型分布；噪声量级（§2.3）；
位置离散双峰（§2.2，该实验条件正确）；贪心路径脆弱性（§2.4）；流派纯度（§2.5，且该结论被强化——
融合卡组输给的是**被削弱后**的 meta 仍全败）。

复测后**修正**的结论：

- meta 之王由 炼金炉（0.972，错误条件）修正为 **先祖墓（0.950）**，炼金炉次之（0.934）；
  当前卡组池中**未发现对新王的确定性克制**（最接近：炼金炉 wr=0.438、瘟疫长柄刀 wr=0.495）。
  旧版「王被快速注射系统/智者之杖克制」系错误条件下的产物；快速注射系统复测 avg=0.699。
- 锚点内 RR 与 meta 胜率相关由 -0.18（错误条件）修正为 **+0.30**：方向转正但仍弱，
  「同 beam RR 不能作为外部强度目标函数」的结论保留、措辞弱化。
- 流派表中各代表卡组的 meta 胜率以复测值为准（§2.1 表已更新）。

## 0.2 第二次复测（2026-08，C++ 批量评估层上线）

阶段 1 的 Python 规则复刻被发现有**第二处漂移**：YAML 数值列表的档位映射从物品的 MinTier 起
（如 智者之杖 Silver 级，`Custom_1: [5,10,15]` 实为 silver/gold/diamond），
而 `gdf_conditions.py` 按 bronze 起的绝对档位索引——Silver 起步物品的 overridable 覆写全部错位
（智者之杖 custom_1 误为 12，GDF 实取 7；挎包 误为 7 实取 4）。该错误由 C++ 批量评估层
（`engine/meta/main.cpp`，复用 GDF 物品规则代码）与 CLI 路径的逐局对照暴露。
matrix_l8_v2（当前真值）与 v1 的主要位移：

- **智者之杖 0.894 → 0.149**：其「精英」地位完全来自错位覆写；在 GDF 自身（正确）取值下
  它并非精英——GDF 仍把它选为锚点 top1（RR=103），成为「同 beam 评估失真」的新例证；
- 连锁反弹：快速注射系统 0.699→0.790、冰霜之怖 0.761→0.815、永恒火炬 0.813→0.850；
- v2 Nash 支撑：先祖墓 0.535 / 炼金炉 0.398 / 快速注射系统 0.067（v1 中的 腐朽圣像 出列）。

**结构性结论**：Python 复刻规则已两次漂移（quest 丢弃、档位错位）。此后评估统一走
**C++ 批量端点 `bazaararena_meta`**（与 GDF 同一份物品规则代码，与 CLI allowTie=true 逐局一致，
约 3.4 万局/秒 @ 24 线程；Python 不再复刻任何物品规则）。

## 2. 关键实证发现

### 2.1 meta 结构：多流派生态，而非单一 meta

全锚点 top1 中 57%（77/134）共享同一核心（力量药水+永恒火炬+采掘工具），看似收敛；
但跨锚点循环赛显示这是**评估池内卷的假象**——真正的精英层高度多样：

| 流派 | 代表卡组（锚点） | meta 胜率（复测） | 引擎核心 |
|------|------------------|-----------|----------|
| 遗物再生引擎 | 先祖墓 | **0.950** | 先祖墓(Q3)+魂戒+双魂石+蛇怪之牙 |
| 药水引擎 | 炼金炉 | 0.934 | 碎瓶+沸腾烧瓶+炼金炉+飞行药水 + buff 药水 |
| 减速控制 | 时间之砂 / 马格努斯的股骨 | 0.895–0.90 | 时间之砂+嗅盐+灼烧减速魂石+瓶装龙卷风 |
| 智者之杖爆发 | 智者之杖 | 0.894 | 智者之杖（占位技能数，见 §2.6 警告） |
| 天平充能 | 天平 | 0.83 | 天平（居中）+永恒火炬+智者之杖 |
| 图书馆引擎 | 灼烧减速/冻结魂石 | 0.71–0.73 | 图书馆+采掘工具+永恒火炬+空白石碑 |
| 剧毒武器 | 瘟疫长柄刀 | 0.72 | 瘟疫长柄刀+蕨叶蜘蛛+毒液 |
| 自毒注射 | 快速注射系统 | 0.70 | 腐朽圣像+快速注射系统+肾上腺素调节服 |

- **锚点内 RR 与 meta 胜率相关 +0.30**（弱相关，解释方差 <10%）：锚点池的构成而非卡组绝对强度主导 RR。
  反例对照：符文巨斧 RR=89（全场最低）→ meta 0.46，与 RR=141 的先祖墓（meta 0.95）相差近 50 分的 RR
  完全没有反映真实强度差距的方向与幅度。
- **非传递性**：上半区 79 卡组中 1250 个 A>B>C>A 循环（≥0.6 阈值）。
  近似混合 Nash 的支撑仅 3 个卡组（炼金炉 0.51 / 先祖墓 0.43 / 腐朽圣像 0.07，exploitability≈0.0004）——
  支撑成员 ≠ 平均胜率头部（时间之砂/马格努斯的股骨/智者之杖均不在支撑中），
  「均衡里站得住」与「平均胜率高」确实是两个不同的解概念。
- **成对胜率 U 型分布**：0–0.1 与 0.9–1.0 两段合计约 43%，中间带（0.2–0.8）约 36%。

### 2.2 位置与排列

对同一 multiset（天平充能阵）的 5 个排列变体做 61 局系列赛：

- 天平**居中**（左右物品数相等）的 3 个排列互相对局为 0.46–0.53（n=61 下统计不可区分）；
- 居中 vs 偏离一格 / 置于边缘 = **61-0 / 61-0**。

**阶段 2 复验（`scripts/meta_search/perm_constraints.py`，约束提取 → 等价类划分）**：
该 multiset 的 5040 个唯一排列被划为 2020 个机制等价类，其中**居中类仅占 7%**（360/5040）——
随机插入选中居中布局的概率极低，这正是贪心插入位循环赛浪费预算且易漏解的量化解释。
类内代表对局 wr=0.500±0.122（不可区分），类间居中 vs 非居中 wr=1.000（碾压），与基线一致。
全 meta 134 卡组的压缩统计：等价类/排列压缩比中位数 2.5×；
**相当多卡组完全无位置约束**（如某 9 件卡组 362880 排列 → 1 类），对这些卡组的全部排列评估都是纯浪费。

结论：位置价值由离散机制约束（奇偶计数、相邻、最左/最右）决定，呈全有或全无；
满足约束的排列类内部近似等价。这证实了 bazaar-core.md 的「等价排列」判断，并给出可操作形式：
**位置约束可从物品 YAML 的能力 AST 机械提取**（已验证可行：Mak 池 140 件中 20 件含位置条件，
见 `tag_extract.json` 的 `positional` 字段；天平为 `Eq(Count(左), Count(右))` 型约束）。

### 2.3 噪声与评估预算

同一对局、21 局系列赛、8 次独立重复：

- 均势对局（炼金炉 vs 符文药水）：均值 0.494，**sd=0.088**，观测区间 [0.333, 0.619]；
- 克制对局（炼金炉 vs 快速注射系统）：均值 0.229，**sd=0.127**，观测区间 [0.048, 0.429]。

GDF 现行 Bo5 单次淘汰在中间带的误差约 ±0.2——瑞士轮与剪枝决策的相当一部分是噪声抽签。
但 U 型分布意味着：多数对局用极少局数即可定性强弱，**预算应集中在中间带**（自适应序贯抽样）。

**Bo5 误判审计（阶段 1 复测矩阵上的解析计算）**：以复测矩阵的胜率点估计为真值，
Bo5 系列赛判错方向的概率在全矩阵 8911 对局上平均 **11.1%**；其中 19.9%（1769 对）误判率 >25%（近似抽签）、
8.4%（751 对）误判率 >40%。GDF 每档要做一连串此类淘汰决策，误差沿搜索路径复利式累积。

### 2.4 贪心路径的脆弱性与偶然性

追溯 3 个精英卡组在其锚点搜索中的逐档存活（按 multiset 前缀匹配 beam top10）：

- 炼金炉（meta 第一）：size=7 时**无任何前缀存活**，size=8 靠其他分支汇合（沸腾烧瓶经多路径合并进入）复活，最终 rank 1。
- 快速注射系统（meta 第二）：size=7、8、9 连续无前缀存活，最终 deck 的 瘟疫长柄刀 从未出现在任何中间档 beam 中，纯靠末端汇合拼成。
- 天平：size=9 断裂，size=10 复活。

即现行 beam 的「多路径汇合」机制**偶然地**救了这些精英；换一个随机种子、或 k 更小，它们就会永久丢失。
贪心真正的盲区（中间形态全弱、且无替代汇合路径的组合）无法从搜索结果中直接观测——这是认知黑洞，
只能靠**机制先验提议**（见 3.2）或替代模型主动覆盖。

### 2.5 流派纯度（跨流派融合的失败）

手工构造两个「强强融合」卡组（自毒注射×药水引擎、注射×减速控制），对 5 个顶级卡组全部 **0-31**。
引擎需要临界质量，格子被两套引擎分薄后两边都不达标。
含义：卡组结构 = **引擎核心（流派内饱和）+ 填充位（流派无关优质件）**；
搜索的变异算子应是「换引擎 / 换填充」，而非「任意换物品」。

### 2.6 模拟器数据警告（影响一切搜索结论）

- **智者之杖**：伤害 = Custom_0 × Custom_1（技能数量占位默认）。**最终定论（§0.2）**：
  GDF 实际取值 custom_1=7（Silver 起步列表的正确槽位），该卡 avg 仅 **0.149**，并非精英；
  此前观察到的强势分别来自「占位 12/15」（敏感性测试）与「Python 错位覆写 12」（v1 矩阵）。
  任何含 智者之杖 的历史结论均按此修正。
- 任务物品在 L8 按规则**自动满进度**（永恒火炬 Q7 等），与真实游戏同名物品强度可能有系统性偏差。
- 建议：任何「优质阵容」结论应附带**数据敏感性检查**（对占位默认值做扰动重测）。

## 3. 方向建议（对 bazaar-core.md 的实证修正与具体化）

### 3.1 解概念与外环：PSRO 被确认，且比预想便宜

实证支持：非传递循环密度、meta 之王的确定性克制者、RR↔meta 去相关，三者共同否定了标量解概念。
同时本次实验顺手证明了工程可行性：**144 卡组 × 全对全 × 15 局在进程级并行下约 20 分钟**；
矩阵填充与 Nash 求解（LP/支撑枚举）都是小事。真正的开销在 best response 子问题——
建议 BR 接受度用「对当前 meta 混合 σ 的加权胜率 + exploitability 增量」，而非对单个对手。

### 3.2 提议机制：引擎模板 × 填充位（新的具体结构）

卡组 = 引擎核心 + 填充。据此设计两级提议：

1. **引擎模板库**：从机制标签（下方 3.4）聚类出的协同簇中，枚举 3–5 件的核心组合
   （如 {碎瓶, 沸腾烧瓶, 炼金炉}、{快速注射系统, 肾上腺素调节服, 腐朽圣像}、{天平, 永恒火炬}）。
   模板带**装配约束**（天平需居中 → 总物品数奇偶与槽位规划；图书馆需无武器；魂石变体互斥）。
2. **填充位搜索**：在模板固定后，剩余 3–6 格用贪心/局部搜索填「流派无关优质件」
   （力量药水、能量药水、无敌药水、琥珀、空白石碑等通用件，从 elite 频率表软先验取样）。

这直接规避贪心的「中间形态必死」盲区：模板的中间形态**从不被单独评估**，评估只发生在整卡层面、且对手是 meta。

### 3.3 评估层：自适应预算 + 约束类排列（横切）

- **排列**：从物品 AST 提取位置约束（已实现原型），把排列空间切成约束等价类；每类只评一个代表；
  类间差异 > 噪声阈值才消耗真模拟。
- **预算**：对局先打少量局（如 7 局）分带——落入一面倒带即停，中间带追加到 CI 收敛（如 ±0.05）。
  预期总预算比均匀 BoN 降一个量级，且杜绝 Bo5 抽签式淘汰。
- **缓存与复用**：同一 multiset（约束类代表）的评估结果跨迭代缓存；禁止 GDF 现行「每批重新加盐、结果不缓存」的浪费。

### 3.4 机制先验：物品标签体系（辅助文档化的起点）

从 YAML 机械抽取 + 实证频率校正，Mak L8 的物品画像可分四层（完整抽取见 `tag_extract.json`）：

| 角色 | 定义 | 实证成员（elite 频率） |
|------|------|------------------------|
| 引擎核心 | 提供循环增益（充能/装填/多重）且需体系配合 | 炼金炉、沸腾烧瓶、碎瓶、天平、图书馆、快速注射系统、肾上腺素调节服、采掘工具 |
| 流派放大器 | 按流派密度/状态缩放 | 瘟疫长柄刀、蕨叶蜘蛛、火爪、秘密配方、魂戒、坩埚、酸液槽 |
| 通用填充 | 单件即强、流派无关 | 力量药水、能量药水、无敌药水、琥珀、空白石碑、嗅盐、永恒火炬 |
| 构筑约束件 | 带装配/奇偶/纯度约束 | 天平（居中）、图书馆（无武器）、魂石变体（互斥）、镜子（相邻复制）、酸液槽（类型数） |

用途：软先验分配搜索预算（不硬剪枝——「多数物品本等级不好用」应以概率倾斜而非排除表达）；
并为 MAP-Elites 的行为描述子提供「流派轴」（引擎类型、输出构成、控制密度）。

### 3.5 建议的落地顺序

1. 把本次实验管线工具化入库（并行枚举器、CLI 系列赛 harness、矩阵构建+Nash 求解）——这是一切后续迭代的测量底座；
2. 实现排列约束类提取 + 自适应评估预算（独立可验证，立即降低所有搜索的成本与噪声）；
3. 在矩阵上跑 Double Oracle：BR 先用「现有 GDF 枚举 + 引擎模板手工库」充当提议器，验证外环收敛性与 exploitability 下降；
4. 最后才考虑替代模型（路线 C）——前提是 1–3 积累的（卡组, meta 胜率）数据量足够。
